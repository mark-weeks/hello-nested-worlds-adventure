## Policy and implementation

[ADR-021](../decisions/ADR-021-m3-history-narration.md) defines the bounded policy.
An original action, accepted delayed work, an arriving ripple and a terminal
outcome now have distinct narration. An acceptance remains a historical
acceptance fact after landing; current pending counts still come from M2's
authoritative reads. Shared joins and admission no-ops create no action or credit.

| Path | Evidence and correction |
|---|---|
| HTTP `/act` | `accept_verb` commits the same origin, initial ring and optional delayed work. After commit, the shared notice reads that origin; personal acceptance flavor stays in the response. The separate origin-pressure notice still animates but adds no duplicate feed line. |
| CLI `_do_scale_verb` | Uses the same acceptance helper. Its existing approximate wait/echo response stays intact; later history and pump notices resolve its recorded source. |
| Cast `_persona_act` | Tender/scholar actions use the same helper, with recorded cast labels. No taxonomy, inferred presence, new memory, or revisit behavior is added. |
| Staged causality | Each arrival retains `_origin`, actor payload and delivery ID. M1's retained queue supplies `source_event_id`. A transient event reference selects the committed row for notification; it is never serialized into the causal payload. SCALE_ACT changes pressure remotely, not substance. |
| Maturation | V1 still lands absolute patches and v2 still interprets its accepted operation. Both notices select the existing landed row. V1 can resolve through the retained delivery reference; v2's direct source reference must agree. Explicit terminal-no-op flavor survives. |
| History/chronicle | One read projection validates explicit source/delivery references against world, receiving node, kind, verb, origin and event ordering. It returns source number, canonical places, recorded actor label and prose. It never matches by display name or timestamp. |
| Live clients | Both clients use the shared narrator for projected notices and historical rows. Causal animations retain strength. M2 refresh IDs, personal response ownership and navigation protection remain intact. |
| Existing speech | `/speak`, `/agent/voice` and CLI node speech already load node history. Their dynamic history block now consumes the same narration instead of saying that an arriving echo was a local act. No external model call was needed to verify the supplied context. |

Pages of up to 200 rows require at most **three additional SELECTs**: one per
referenced queue and one for all explicit source IDs. A mixed page uses four
SELECTs including its base history read. Chronicle's existing count/min queries
are unchanged. Internal image-history reads keep their 1,000-row window and use
200-row chunks. Production pump notifications project once per seed per bounded
drain (64 causal / 32 maturation candidates), after all individual commits.
Each send remains isolated; read/send failure cannot retry committed work.
Accepted actions require only their one origin read. No world hydration, ancestor
search, source recursion, new index or per-history-row lookup is introduced.

## Before/after endpoint evidence

The [portable probe](2026-09-08-m3-history/endpoint_probe.py) runs against an
explicit checkout and uses real `/act`, `/world`, `/history` and `/chronicle`
endpoints, plus real CLI and cast producers. It captures the producer/pump
broadcast envelopes, the shared JavaScript narrator and speech-history text.
Only disposable queue clocks are advanced. Browser tests separately verify the
actual WebSocket transport, rendering and reload.

The same five source actions produce **24 history rows** in both versions:
one immediate seed, four accepted kindles (Ada, Bea, CLIVisitor and Tessera),
15 arriving ripples and four delayed outcomes. The probes preserve raw mechanical
facts so comparison can exclude wall-clock timestamps without reconstructing effects.
All 24 raw rows match exactly in ID, canonical node, kind, player label, payload,
delta, node version, strength and actor identity between the two runs.

| Surface | M2 baseline | M3 |
|---|---|---|
| Cast ripple at a different scale | “Tessera chose to kindle at Ashen Ember Sphere” | “A ripple from Tessera's kindle at Mossbound Bell Disc [111] reached Ashen Ember Sphere [11]. Source action #5.” |
| HTTP/CLI ripple | “someone chose to kindle…” | The recorded Ada, Bea or CLIVisitor label, original Galaxy address and distinct source action number. |
| Original delayed choice | “Ada chose to kindle…” | Adds “A delayed outcome was accepted. Action #2.” It does not claim that density already changed. |
| Four delayed landings | Four identical place/flavor lines | Each identifies its own source action (#2–#5), recorded label and actual material completion. |
| Node/inhabitant speech context | “scale act, by an unknown presence” at the receiving Universe | The same source-attributed ripple sentence a player sees, with no claim the verb happened at that Universe. |

## Compatibility, gaps and irreversibility

No genuine persistence gap requires a new write path for M3. Retained M1
delivery/source IDs cover current HTTP, CLI and cast actions. Older `_origin`
and actor payloads support only the place/label they actually record; without an
exact reference the prose says the exact original action is unrecorded. Missing
or contradictory references never borrow another row's actor. Absent evidence
of origin/delay/material change yields a trace, not a fabricated choice.
Old clients may ignore the additive narration fields; refreshed clients consume
them. Compatibility fallback text is conservative when an older server omits them.
The full chronicle still uses its existing pagination; source action numbers and
canonical node addresses identify the source without adding a navigation system.

Wayback bypasses narration entirely: it stays actor-blind and reconstructs from
stored deltas. No acceptance, v1/v2 interpreter, causal law, completion fence,
born-node, canonical identity, hinge, seal or human/agent puzzle rule changes.
ADR-013's broader situation proposals remain Proposed. No M0/M5 content, M4
revisit behavior, journal, profile, inventory, geography or general event engine.

**Irreversibility check:** none — no migration, golden re-pin or new chronicle
row/write path. The diff adds read projections, transient notification references
and presentation only; stored deltas, born nodes, hinge and era banks are unchanged.
