## Findings and changes

The puzzle-evidence endpoint was absent from the read limiter's route list.
A regression reproduced an ordinary read consuming the quota while the evidence
request still opened and pinned a question. API reads now inherit the limiter by
default. Static shells/assets and health retain their exemption, as do existing
cheap control reads (world list, presence, saved position) and the separately
protected WebSocket upgrade. Real HTTP tests cover the data routes, future/unknown
API paths, the exemptions, and rejection before a puzzle instance is stored.

Journal output was limited to eight consequences, but the per-node query still
scanned unrelated chatter at that same node. Overlay-version and puzzle-epoch
reads likewise scanned non-material history. Migration 0024 adds two partial
indexes: material rows ordered per world/node/event, including their version;
and puzzle-rearm rows per world/node. The affected queries prefer them, falling back to the same query without its
index hint if an older live restore has removed that particular index.
Evidence lookup and both puzzle-attempt branches ask for just their node's epoch. Global activity counts remain
proportional to the number of events because that operation counts all events;
this batch introduces no derived counter, retention policy, or history deletion.

The new `work-report` CLI takes one read-only snapshot of all three queues and
unsettled situation decisions. It reports pending/due/eligible work, recorded
errors, backoff, oldest due age, and earlier-step blockers, with bounded samples
and explicit truncation. It does not select payloads, actor identities, credentials,
or journals. Error strings remain operator-only context. Reports can run beside a
writer, never create a missing database, and reject unsupported old schemas without
migration. Existing inspection and pending-only retry helpers now also accept
`situation_work`; the generic causal/maturation interpreter still rejects that queue.

These are reporting, query and backup-file-format changes. They do not change delivery semantics,
retry intervals, version interpretation, situation order, action receipts, or
post-commit notification rules. The recovery guide explains the queues' different
attempt-count/error-retention semantics rather than pretending they are identical.

## PR #101 recovery follow-up

Review reproduced two recovery gaps: the new hard index hints failed after a
schema-23 backup was restored into an already-initialized process, and WAL-header
backup copies could not be reported from a read-only directory. New regressions
cover recap, global/scoped overlays and epochs after a real restore with migration
explicitly forbidden; both new and existing WAL backup targets become standalone
snapshots readable from a `0555` directory with a `0444` database file, without
creating sidecars or changing database bytes. The permission checks ran as the
ordinary local user (uid 501), not root. Live WAL mode remains unchanged.

Simply removing the hints failed the recap and scoped-overlay cost budgets. The
final queries retain the fast index and retry only its exact missing-index error.
Other database failures are not swallowed, and disaster restore does not reapply
potentially faulty migrations. Snapshot creation converts only the destination to
DELETE journal mode. Reports continue to use normal read-only SQLite locking;
there is no automatic immutable fallback for a possibly live database.

Both puzzle-attempt branches now scope epoch reads to the attempted node. The
regression exercises solved and unsolved sessions, accepts the current epoch and
rejects a stale one with 10,000 renewals elsewhere. The SQL budget covers epoch
lookups only; other co-op hydration queries are outside that measurement. Each
branch exceeded the budget before its call-site fix. The CLI test now runs from
a deliberately unrelated directory using an absolute entrypoint; all ten report
tests also pass when pytest starts in `tests/`.

The focused history/report pass has **22 passing tests**. A repeat of the
[history probe](2026-09-14-tech-debt/history_probe.py) retains the reported SQL-step
improvements; [updated measurements](2026-09-14-tech-debt/after.json) include this
follow-up. The full `ENFOLDED_E2E=1 ./scripts/check.sh` passed again after the fixes:
Ruff, **1,135 Python tests** (143.96 seconds), **113 Vitest tests**, frontend build
and unchanged bundle freshness, installed-wheel smoke, and **43 Playwright tests**

resolve; diff whitespace checks pass. [Verification record](2026-09-14-tech-debt/verification.json).
