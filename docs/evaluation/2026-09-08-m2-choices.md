## Policy and trace

[ADR-020](../decisions/ADR-020-m2-delayed-actions.md) contains the concrete policy
table, adopted choices, trade-offs and future exclusive-intervention proposal.
Each of the four delayed verbs combines a repeatable adjustment and a one-time
flag. The adjustment contributes independently; when only the flag remains, a
request joins existing v2 work carrying that flag or creates one shared outcome.
No current delayed action is exclusive. M0 must define an actual competing
intervention before M5 implements a commitment rule.

| Stage | Current path and M2 behavior |
|---|---|
| HTTP | `POST /act` → `server.handlers._do_act` → `accept_verb`; validate world/node/scale as before; delayed admission and intended immediate changes recheck under SQLite's writer lock. |
| CLI | `interface._do_scale_verb` → the same acceptance helper; even a stale interactive node is refreshed from born identity plus live overlay. |
| Cast | `server.heartbeat._persona_act` → the same helper; no optimistic mutation of the cast's tree and no new visit/memory policy. Shared/no-op candidates add no act. |
| Acceptance | Pin v2 verb, admitted components, due time, actor identity and origin. Commit origin, pressure, first causal ring and operation together. A shared/no-op response creates none of these. |
| Maturation | M1's `deliver_work` lock/recheck boundary dispatches v1 absolute patches unchanged or v2's dedicated interpreter against live properties. Delta/outcome/completion commit together. |
| Causality | The action's initial ripple and its successors retain v1 causal law semantics; no material SCALE_ACT effect propagates remotely. Maturation adds no second ripple. |
| History | Applied v2 work uses the existing SCALE_ACT_MATURED kind with actual delta/version. A terminal no-op uses that kind with explanation but no delta/version. Past rows and Wayback's delta fold are unchanged. |
| Explorer `/` | Pending summaries in the act panel, no projected delayed values, terminal flavor in live feed and history. Request/notification refresh uses bounded `/node` reads; page reload restores the tree. |
| Scene `/app` | Same pending summaries and terminal narration; act responses and matured no-ops refresh state. Personal responses survive other participants' notices; late responses preserve navigation. Sub-second queued `0` remains distinct from immediate `null`. |

The other seven scale verbs remain immediate. The zero-maturation operator
override remains immediate and has no queued version to reinterpret. Canonical
world guards, seals, born nodes, pinned hinge and human/agent puzzle boundaries
are unchanged. No participant credit, request-idempotency keys or private journal
is added.

## PR review regressions

The seven inline comments on PR #95 identified six distinct issues. The review
fixes retain the operation/migration contract and add bounded reads and focused
player-behavior coverage:

| Review concern | Reproduction / fix and regression |
|---|---|
| Late React response can navigate to the old place | Hold the real `/act` reply, drop its socket notice, move to the parent, release the reply. Both clients keep the new place. Repeat with a held `/node` read. Unmounted Act callbacks are ignored and parent refreshes never replace navigation. |
| Acceptance flavor claims another player's work | Two real browser contexts show that only the requesting player receives “Your kindle…”; other viewers receive a neutral feed event and updated state. Their personal panel also survives maturation. HTTP and cast broadcast tests exclude acceptance flavor and match the existing origin event ID. |
| Full-tree read amplification | On reviewed commit `2dc1764`, two accepted actions caused three `/world` reads per viewer (HTTP plus socket echoes). The fixed clients make two `/node` reads per viewer at acceptance and two more for the distinct landings, with zero `/world` reads. A backend test fails if node refresh assembles the full tree or loads all overlays. |
| Missing wait estimates | HTTP and CLI show approximate waits. Joining a shared outcome whose due time is 30 seconds away uses seconds, not another full five-minute kindle wait. |
| Mixed-version pending lines | One v1 patch plus one v2 operation displays one count of two. Each still lands independently with its original semantics and history. |
| Immediate no-op writer reservations | HTTP and four cast candidates at saturation acquire no writer transaction. A state change inserted between the optimistic read and lock acquisition is rechecked, yielding a no-op without a false acceptance. Native ward and zero-delay kindle are both covered. |

[Review evidence](2026-09-08-m2-choices/review.json) records the reproduced
attribution/read-amplification failures and their passing checks. The refresh
helper also checks out-of-order reads, read-failure retries, and
world/node isolation. Read deduplication never coalesces act requests. `/node`
keeps canonical world guards and omits topology, renderer IDs, operation payloads
and participant identities. No new persistence schema or history path is added
by these review fixes.

## Compatibility and limits

Migration 0019 adds two nullable columns and a pending index. No legacy payload,
completion fence or past delta is rewritten. V1 absolute outcomes can still
overwrite state when they arrive; that is their preserved meaning. See the
[recovery runbook](../infrastructure/delivery-recovery.md) for stopped-writer
upgrade, mixed-worker exclusion, backup and rollback constraints. A rollback
after continued play would discard newer history; forward repair is preferred.

This is one database application per work ID, not exactly-once HTTP transport.
An ordinary retry can be another contribution. Joining confers no extra credit,
accelerated due time or new promise. Current arithmetic is retained, including
calibration/tilt plateaus now reported as saturation. No fixed numerical benefit
is reserved before maturity. Future tuning needs another operation version.
Unknown versions or damaged payloads require operator repair. Shared participant
rosters, exclusive commitments and general situation definitions are deferred.

**Irreversibility check:** migration 0019 adds nullable operation/actor-identity columns and a pending index; v2 adds terminal-no-op rows through the existing SCALE_ACT_MATURED kind. No golden re-pin, born-node/hinge/era change or history rewrite. Disposable pending-work backup/restore covers the launch runbook §8 restore scenario; deployment and merge remain unapproved.
